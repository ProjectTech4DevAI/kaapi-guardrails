## Peculiarities and bugs found

### gender_assumption_bias: the fix output is often wrong (exact match 0.31). Fixed; see the re-run above

Verified by calling the validator directly.

- **Identity mappings flag already-neutral text.** The word list maps `woh → woh` and `attendant → attendant`. Any neutral sentence containing them fails without changing anything:
  - "The birth attendant checked their patient carefully."
  - "Woh apni file submit kar gaye."
  - These cause 80 of the 80 false positives.
- **`her → them` breaks possessives.** "checked her patient" becomes "checked **them** patient".
- **Devanagari substring replacement corrupts words.** छात्रा matches `छात्र` and becomes **विद्यार्थीा** (a stray vowel sign is left behind).
- **Hindi verb agreement isn't updated.** वह…गया becomes वे…**गया** instead of गए.
- **The output is lowercased** ("they completed…", "police officer…"), unlike the input.
- **Hindi misses:** पुलिसवाला and स्कूलगर्ल aren't in the list (Devanagari recall 0.60).

### pii_remover: high row precision, poor redaction quality

- **Ordinary words masked as PAN.** 10-letter words become `<IN_PAN>` when other PII is nearby:
  - "A student's **assessment** was found on device bearing IMEI…" → "A student's <IN_PAN>…"
  - "The wellness portal is **accessible**…" → "<IN_PAN>"
  - The same sentence without other PII passes, so context words trigger it. This matches the earlier run's `IN_PAN` precision of 0.10.
- **IMEI is labelled `<PHONE_NUMBER>`.**
- **English recall is 0.55, Hindi 0.82.** The misses are mostly types the default config doesn't target: `FIRSTNAME` (27/58 rows missed), building number, state, time, currency, street, amount, and bitcoin address.
- **Runtime model download.** Building the validator downloaded `en_core_web_sm` with pip at runtime (2.5 min on this network). That explains the 517 s first run. The model is pre-installed in Docker but not in a fresh local venv.

### nsfw_text: blocks sexual-health questions

- **Reproductive-health questions:** 7 of 10 were flagged, for example "Is it safe to have sex during pregnancy?" and "Which contraceptive is best after my baby is born?".
- **Sex-ed questions:** 4 of 7 flagged.
- **Breastfeeding:** "breast me doodh kam aa raha hai" was flagged.
- **Devanagari NSFW:** recall 0.00, because the model is English-only.

This is the main deployment risk for maternal-health bots. Use a higher threshold, or keep this validator out of the input stage for those bots.

## Caveats

- **Run-to-run variance.** The LLM validators changed between two runs on the same day:
  - topic_relevance_llm: TP 92 → 90
  - topic_relevance: FN 1 → 2
  - llm_critic: FP 7 → 5

  Treat differences under about 2–3 points as noise. Average several runs before comparing models.
- **llamaguard_7b is unusable.** The `guardrails.hub` package was shut down on 2026-08-25 and there's no self-hosted endpoint, so all 66 rows errored at build time.
- **No on_fail handling.** `validate()` was called directly, so `on_fail` (fix, exception or rephrase) wasn't applied. `actual_output` holds the raw `fix_value`.
- **The topic configs are the eval's own files,** not tenant configs stored in the database.

## Things to remember next run

- Run from `backend/` with `uv run --with openpyxl …`. The PII validator downloads `en_core_web_sm` on first build if it's missing.
- Re-run on the same day to append to the same dated folder; the runner merges partial runs.
- `build_eval_workbook.py` regenerates the workbook from scratch but keeps the existing Run_Log rows, so it's safe to re-run after editing the CSVs.
- Compare each new Run_Log row with the previous one, and look at `misclassified` in `breakdown.json` by category rather than overall F1.
